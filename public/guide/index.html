04 · Data & services

What sits behind the menus

The Studio is a control plane for one Fastify API. Project data is isolated by PostgreSQL schemas and roles; object bytes live on disk; all control-plane state lives in platform tables.

Service architecture

Fastify is the gateway. Dedicated services implement auth, database metadata, PostgREST-style data APIs, storage, realtime WebSockets, isolated function workers, durable jobs, diagnostics, and verified backups.

FastifyPostgreSQL / PGliteWebSocketWorkers

Isolation model

Each project gets proj_<slug>, role_<slug>, and role_<slug>_rls. JWT claims power auth.uid(), auth.role(), auth.email(), and auth.jwt() inside transactions.

RLSLeast privilegePer-project schema

Control-plane tables

platform_organizations, platform_projects, platform_users, platform_sessions, platform_api_keys, platform_secrets, platform_storage_*, platform_realtime_*, platform_functions, platform_jobs, platform_backups.

Client plane

Public requests use project API keys. Signed-in users add a Bearer JWT. REST, RPC, Auth, Storage, Functions, and Realtime all resolve to the same project-scoped policy layer.

05 · Phone as server

Run MARI BASE on an Android phone

The Android companion app is a client. To make the phone itself the server, run the Node.js backend in Termux. This is intended for a local lab or offline demo; use a real host and PostgreSQL 16+ for production.

Phone as client — recommended

Server runs on a computer, Docker host, or VPS. Phone enters an HTTPS URL. Best reliability, security, and performance.

Phone as server — local lab

Termux runs Fastify + embedded PGlite. Bind to 0.0.0.0, then connect via loopback or trusted LAN. Keep the phone awake and charged.

!iPhone note: Termux is Android-only. An iPhone can be a browser/client, but this project cannot run its Node server natively on iOS. Use a computer, VPS, or external host as the server.

Setup in six steps

Install Termux and Node 22+

Install Termux from F-Droid or its official GitHub release. Node.js supports Android through Termux packages; MARI BASE requires Node 22 or newer.

pkg update && pkg upgrade -y
pkg install -y git nodejs-lts tmux curl
node --version   # v22.x or newer
npm --version

Download the platform and install dependencies

Use your fork or branch containing npm run start:phone. If the LTS package is older than 22, install nodejs, switch mirrors with termux-change-repo, or use PRoot with Node 22.

git clone https://github.com/Emmanuel001afk/MAARY-BASE.git maary-base
cd maary-base
npm ci

Start the server on all interfaces

The launcher creates .env if needed, sets HOST=0.0.0.0 and PORT=4100, uses PGlite, enables migrations, prints the phone's LAN IP, and starts the API.

npm run start:phone

# Equivalent manual command:
cp -n .env.example .env
HOST=0.0.0.0 PORT=4100 \
DATABASE_URL=pglite://./data/postgres \
AUTO_MIGRATE=true npm run dev

Verify readiness

The Android companion checks both endpoints below before it will open the Studio. A ready response must contain "status":"ready".

curl -f http://127.0.0.1:4100/ready
curl -f http://127.0.0.1:4100/v1/platform
ip -4 addr show wlan0 | grep inet

Connect a browser or companion app

Use http://127.0.0.1:4100 on the server phone. From another device on the same Wi-Fi, use http://<phone-LAN-IP>:4100 and enable the native app's cleartext HTTP option for trusted LAN development only.

Studio: /Mobile client: /mobile/Guide: /guide/

Keep it awake and protect the data

Disable battery optimization for Termux, keep the notification and charger connected, run termux-wake-lock, and use tmux. Back up data/, storage/, and .env.

termux-wake-lock
tmux new -s maary
# Inside tmux:
cd ~/maary-base && npm run start:phone
!Do not expose raw HTTP to the internet. For remote access, place a trusted HTTPS tunnel or reverse proxy with a valid certificate in front of the phone, set a restrictive CORS_ORIGIN, replace all development secrets, and use external PostgreSQL for production.

06 · Connection paths

Which URL should I enter?

The companion expects the server origin only — no /dashboard, /mobile, query string, or fragment. It verifies /ready and /v1/platform.

Same phone server
http://127.0.0.1:4100

Use when Termux and the browser/companion run on the same Android device. The native app has a Phone server (4100) preset.

Trusted Wi-Fi LAN
http://192.168.1.42:4100

Replace with the phone's wlan0 address. Tick “Allow cleartext HTTP for local / LAN development” in the native companion. Guest Wi-Fi or AP isolation can block this.

Android emulator
http://10.0.2.2:4100

Use for a server running on the computer that hosts the emulator. The emulator's own 127.0.0.1 is not the host.

Remote / internet
https://api.example.com

Use a valid TLS certificate through a tunnel or reverse proxy. Remote plain HTTP is deliberately rejected by the Android companion.

✓First account: open the Studio and register an operator. In development the first account becomes Superadmin; in production it requires PLATFORM_BOOTSTRAP_TOKEN.

07 · Troubleshooting

Common connection failures

SymptomLikely causeFix
Node version errorTermux installed Node below 22.Install current nodejs/nodejs-lts, change mirrors, or use PRoot with Node 22.
Works on phone, not laptopServer bound to loopback, different subnet, or AP isolation.Use HOST=0.0.0.0, same Wi-Fi, correct wlan0 IP, no guest network/VPN.
HTTPS requiredRemote URL uses plain HTTP.Use an HTTPS tunnel/reverse proxy with a valid trusted certificate.
Platform not verified/ready or /v1/platform failed.Check both endpoints, database migrations, and storage directory permissions.
Server stops when screen sleepsAndroid battery optimization / phantom process killer.Set Termux battery to unrestricted, run termux-wake-lock, use tmux, and keep the device charging.
CORS errorClient origin is not allowed.Set CORS_ORIGIN to the exact origin, or * only in an isolated lab.
Data disappeared after reinstallPGlite data and object bytes were stored only in the phone checkout.Restore data/, storage/, and .env from a verified backup.

08 · Sources & honest gaps

Research provenance

Supabase Studio navigation was inspected from its open-source repository at commit 9391f60ec973113d69f5fa7a09a4860e50f56a50 on 2026-10-26. The mapping document in the repository lists every source file.

Primary route generator NavigationBar.utils.tsx Product-menu registry mobileProductMenuRegistry.tsx Database submenu DatabaseMenu.utils.tsx Auth submenu AuthLayout.utils.ts Node.js on Android / Termux nodejs.org MARI BASE repository github.com

Deliberately not faked

MARI BASE does not provide Supabase SSO, billing, branching, GraphQL, hosted compute upgrades, vector/analytics buckets, or a managed control plane. The Studio does not show dead links for these.

What is functionally equivalent

Project/organization scope, primary/secondary navigation, Table Editor, SQL + RLS, migrations, backups, auth users/sessions, storage, realtime, functions/jobs, logs, API keys/secrets, and API docs.
